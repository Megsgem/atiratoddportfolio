About the Game

Time Frame: 8 weeks

Team Size: 23

Language/Engine Used: C#, Unity

Main Contributions:

- UI Programming
- Checkpoints
- Player Death & Respawn/Restart System

This is a game I made as part of a team during my Junior Collaborative Games Development module during my second year of university. During the course of this module, I worked with other members of the team, across various different disciplines such as art and design, to implement the different aspects of the game that I was tasked with creating by senior members of the team.

It is a 3D speedrunning platformer game where you play as Cursor and must use your different abilities such as wall running and grappling to traverse the techno-wave cyberspace environment as fast as possible.

Main Menu UI

One of my main tasks and contributions to this project was the programming for the UI in the main menu. This included not only the backend for UI of the main menu screen itself but also for the related screens which the buttons of the main menu screen lead to. The designers within the team had specified that these would be a level selection screen, a controls screen and a settings screen.

I first started working on the functionality for the main menu screen itself such as making sure the player could navigate the buttons on this screen using either the keyboard or a controller or a mouse. I already had some experience doing this from previous projects I had worked on and thus I applied the knowledge I already had to this task.

Checkpoints & Player Death System

Another big contribution I made to this project were the checkpoints in the game as well as related things such as player death and the ability for the player to restart and respawn.

The final version of this system would immediately respawn the player at their respawn location when they hit an obstacle or fell off the course, as well as pausing the timer until the player had respawned. This respawn point is initially the player's start location and is updated whenever the player crosses a checkpoint, setting it to be the checkpoint's position. These checkpoints could only be crossed once so that the player would respawn at the checkpoint they had most recently crossed. The player can also press the R key to fully restart the level, meaning that they not only restart at their start location but that things such as their time and number of collectables collected is reset.

Iterative Development

Throughout the development process, I made sure to get feedback both from other members of my team and through playtesting with people outside of the team. As a result of this feedback, the player checkpoints and death system went through many iterations before a final version for it was decided upon. This ensured that myself, the other members of my team and the people playing the game were happy with the way this system felt.

Even before I actually started creating the functionality of this system, I consulted the design document created by the designers in my team and also discussed the specifics of this system with them so I could fully understand exactly how it was meant to work and feel for the player. Once I had a full understanding of what the functionality of this system should be, I created an initial prototype of this system which had most of the basic functions of this system such as changing the player's respawn point when they cross a checkpoint, ensuring the player could only cross a checkpoint once and respawning the player at the correct place depending on whether they were respawning or restarting the level.

In this prototype, upon death, the player was presented with a menu which allowed them to choose whether they respawned or restarted the level, however, after showing the prototype to both the design team and senior members of the programming team, it was decided that the player should instead just instantly respawn upon death. If the player wanted to respawn, it was decided that they could do this through the pause menu. After recieving this feedback, I created a second prototype which not only implemented the changes suggested, but also had some additional features outlined in the design document which I hadn't yet implemented such as the ability for the player to decide whether the checkpoints in the level were enabled or disabled.

After I created this second prototype, another member of the team created the timer for the level so, I then had to implement functionality for pausing this timer while the player was dead and resetting it when the player restarted the level. I then showed this final prototype to the other memebers of my team and, after a few refinements to make it feel more polished, it was decided that this was the version of the system that would be implemented into the game. However, after feedback from playtesting with other people from outside the team, I made one final adjustment was made which allowed the player to restart the level by pressing the R key as well as through the pause menu.

What I Learned

This was the first game that I made as part of a large team and I learned a lot over the course of the project. Some of the most important things I learned were about what working to create a game as part of a larger team was like such as communicating effectively with others and how to use good version control in this setting. These are skills that I will continue using and hope to further in future team projects.

I also learned many new things while working on this project about UI programming in Unity as well as how to use a JSON file system for data persistence across scenes, both of which are things that I will definitely use when making games in the future.
