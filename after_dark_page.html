About the Game

Time Frame: 36 hours

Team Size: 1

Language/Engine Used: C#, Unity

This is the game I made for the UKIE Student Game Jam 2025 where the theme of the jam was 'Contrast'. The duration of the jam was 36 hours during which I used C# and Unity to program all of the mechanics for the game including the 'switching' mechanic which is central to the gameplay. Since the end of the jam, I have done further work on this game fixing some bugs which remained in the game by the end of the jam and adding some new things which I wasn't able to add during the jam time.

The game is a relatively simple platformer where you have to traverse through each level in order to find the exit and move on to the next. However, in order to do so, the player must use their ability to switch between light and dark as some things only exist in the dark and others only exist in the light.

Switching Mechanic

One of the main mechanics of this game is the mechanics that allows the player to switch between light and dark. Not only is this mechanic the way that the game fits into the theme of the jam as it means that the contrast between light and dark is a central part of the game but it also allows the player to use platforms that they previously couldn't access.

In order to create the functionality for this mechanic, I first created a new script which would handle the changing of state from light to dark. This script is currently attached to the tilemap as the main thing that has to change when the state is changed is the tilemap, both in terms of colour and in terms of its actual layout and while the player's appearance is changed when the switching mechanic is used, this is handled within the player controller script. Within this script I added a string variable which would store what the current state was ('light' or 'dark') and I also added variables to store the SpriteRenderer for the background of the level, the InputAction that would be pressed in order to make the state change, a float to be used as a cooldown timer for the switching mechanic and two Tilemaps and their colliders - one for when the state is 'light' and the other for when the state is 'dark'. Upon initialisation, within the built-in Start and Awake functions, the SpriteRenderer variable and two tilemap colliders are all set to the correct components of the respective objects that they are attached to, the InputAction variable is set to the action in the input system with the name 'Switch' and the state is set to 'light'.

Then, I started creating the actual functionality that would allow the player to switch from light to dark by first making it so that when the correct key is pressed, it checks the value of the cooldown timer to see if the player is able to switch and then sets the variable storing the current state to be the opposite to what it currently is (i.e. if the state is currently 'light' it is set to 'dark' and vice versa). This switches the state when the player presses the key bound to the input action 'Switch' but it doesn't change anything about the rest of the level itself. In order to do this, a check is made to see what the current state of the level is and then, based upon this, the colour of the background is set to either black or white (black if the state is 'dark', white if the state is 'light') and the correct tilemap as well as its collider is enabled while the other tilemap and its collider are disabled.

This makes sure that when the theme is switched from light to dark or vice versa, the colours of the level will invert and different platforms will become visible but I also needed to add some functionality to the player in order to make sure that the player's appearance would change when the state did. I did this by checking what the current state was from within the player controller script and then setting the colour of the player's sprite renderer based on this (if the current state is light, the player's sprite renderer is set to black whereas if the current state is white, the player's sprite renderer is set to white). This makes sure that the player can still be seen when the colour of the background changes.

Movement

Another important feature of the game is the player's movement. This was my first time making a 2D platformer game so initially it was somewhat difficult for me to figure out how to implement some aspects of the player's movement. Making the player move from left to right was fairly simple as this was something I had done in other games but the main thing I experienced trouble with was the jumping mechanic.

Another issue I had with player movement was the fact that the player was able to climb walls which is something that I didn't want them to be able to do as it removed many challenges in the game. I was able to quickly figure out that this issue was because the boolean I used to check whether the player was on the ground was true whenever the player collided with any part of a platform, including the sides of them. I managed to solve this issue by adding an additional collider to the bottom edge of the player which would only interact with the floor and not the sides of the platforms and then making sure the player was only considered to be on the ground when this collider was interacting with a platform.
